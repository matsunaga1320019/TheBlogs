# The Blogs

A shared blog platform built with Django for the Web Engineering (SE01) course project.

## Overview
Users can read blog posts freely. Registered users can write posts.
Posts can be searched by title and filtered by author or date.

## Environment
- Python 3.11
- Django
- Package manager: uv

## Setup
\`\`\`bash
uv sync
uv run manage.py migrate
uv run manage.py runserver
\`\`\`

## Tools
- Black — formatting: `uv run black .`
- Pylint (+ pylint-django) — linting: `uv run pylint blog`
- pytest (+ pytest-django) — testing: `uv run pytest`
- coverage.py — test coverage: `uv run coverage run -m pytest && uv run coverage report`

## Deployment

The project is production-ready and configured for [Render](https://render.com):

- **Hosting**: Render web service (free plan)
- **Application server**: gunicorn (WSGI)
- **Static files**: served by [WhiteNoise](https://whitenoise.readthedocs.io/) with compressed, hashed filenames (no separate CDN/object storage needed)
- **Database**: Postgres in production (via `DATABASE_URL`, parsed with `dj-database-url`), SQLite as the local development default
- **Uploaded files**: the app does not currently accept file uploads, so no object storage is configured

### Environment variables (production)
| Variable | Purpose |
|---|---|
| `SECRET_KEY` | Django secret key (generated by Render automatically via `render.yaml`) |
| `DEBUG` | Set to `False` in production |
| `ALLOWED_HOSTS` | Comma-separated hostnames (Render's own hostname is added automatically via `RENDER_EXTERNAL_HOSTNAME`) |
| `DATABASE_URL` | Postgres connection string (provided automatically by Render's managed database) |

### Deploy with the Blueprint (`render.yaml`)
1. Push this repository to GitHub (already done).
2. In the Render dashboard: **New +** → **Blueprint** → connect this GitHub repo.
3. Render reads `render.yaml`, provisions a free Postgres database and a web service, and sets `SECRET_KEY`/`DATABASE_URL` automatically.
4. Click **Apply** and wait for the build to finish (build runs `uv sync`, `collectstatic`, and `migrate` automatically).

### Deploy manually (without the Blueprint)
1. **New +** → **Web Service** → connect this repo.
2. Runtime: Python 3.
3. Build command: `pip install uv && uv sync --frozen && uv run manage.py collectstatic --noinput && uv run manage.py migrate`
4. Start command: `uv run gunicorn TheBlogs.wsgi:application`
5. Add a free Postgres database (**New +** → **PostgreSQL**) and copy its **Internal Connection String** into the web service's `DATABASE_URL` env var.
6. Set `SECRET_KEY` (any long random string) and `DEBUG=False` in the web service's env vars.

### Local development vs. production
Locally, no environment variables are required — the app falls back to `DEBUG=True` and SQLite automatically. Production behavior only kicks in when `DEBUG=False`/`DATABASE_URL` are set, so the existing local workflow (`uv run manage.py runserver`) is unaffected.
